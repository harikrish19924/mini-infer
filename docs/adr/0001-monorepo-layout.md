# 0001. Monorepo with a separate operator module

- Status: accepted
- Date: 2026-10-08

## Context

tinyinfer has three binaries (gateway, fakemodel, loadgen), shared internal
packages, and a Kubernetes operator. The operator is generated by kubebuilder,
which expects to own its directory layout and pins controller-runtime and
client-go versions.

## Decision

One repository. The root Go module (`github.com/harikrish19924/mini-infer`) holds
`cmd/` and `internal/`. The operator lives in `operator/` as its own module,
scaffolded by kubebuilder in phase 4.

## Alternatives considered

- A single module for everything: kubebuilder's dependency pins would then
  constrain the gateway, and its generated Makefile and layout would clash with
  the root.
- Separate repositories: more overhead and harder to version the gateway and
  the operator together.

## Consequences

The gateway's EndpointSlice discovery uses client-go directly, so both modules
depend on client-go and their versions must be kept in step by hand. A `go.work`
file can tie the two modules together for local development.
